# 毎日8:00・23:50（日本時間）の写真のお題通知

通知時刻は日本時間の **朝8時と23時50分に各1回** です。以前の9〜21時のランダム通知を置き換えます。`notifications.mjs` の `notificationSchedule()` が時刻の唯一の設定元です。古い `NOTIFY_START_HOUR` / `NOTIFY_END_HOUR` は使いません。

朝の通知は「今日のお題、のぞいてみよう。」、本文は「いつもの道に、まだ気づいていない一枚があるかも。芭蕉のお題をヒントに探してみよう。」です。夜は「今日の景色、1枚残してみない？」と、身近な一枚や振り返りへ誘います。通知を開いてもカメラは自動起動しません。

## 実配信への反映

GitHub Pagesの更新だけでは、Cloudflare Workerの配信時刻は変わりません。本番Workerへの別途公開が必要です。現時点で実端末への配信は未確認です。

既にD1・VAPID・PUSH_RATE_LIMITERを設定済みの場合:

1. `node ai-service/build-dashboard.mjs` で生成した `ai-service/dashboard-worker.js` の全文で、Cloudflareの既存 `basho-ai` のコードを更新します（または承認済みの認証環境からWranglerで公開）。AIの処理も含む既存Workerを保持した単一ファイルです。
2. 既存の `NOTIFICATIONS_DB`、`AI`、`IMAGE_RATE_LIMITER`、`PUSH_RATE_LIMITER`、VAPID鍵を保持します。鍵の再生成やD1の再作成は不要です。既存の `0001_notifications.sql` のテーブルをそのまま使用します。
3. Cron Triggerが **`* * * * *`（1分ごと、UTC）** であることを確認します。30分ごとのCronでは23:50に動きません。日本時間8時は前日の23:00 UTC、23:50は当日の14:50 UTCです。1分ごとの起動で配信待ちの端末を順に処理します。
4. サイトのカレンダー内「通知の設定」を開き、時刻表示が朝8時・23時50分になっていることを確認します。古いWorkerなら「通知サーバーの時刻設定は更新待ち」と表示し、新時刻の登録完了とは案内しません。
5. 通知をまだ許可していない端末では「1日2回の通知を受け取る」から登録します。既存の登録は保持されます。テスト通知は押したときだけ送る追加の1件です。

新規設定ではD1で `migrations/0001_notifications.sql` を実行し、D1バインディング `NOTIFICATIONS_DB` を登録します。Rate Limiterは `PUSH_RATE_LIMITER`、Namespace ID `1003`、Limit `30`、Period `60`秒です。公開鍵は `VAPID_PUBLIC_KEY`（Text）、秘密鍵は `VAPID_PRIVATE_KEY`（Secret）を使用し、秘密鍵をチャットやGitHubへ貼らないでください。

## 配信と端末の制約

- 通常通知は各端末で朝・夜それぞれ最大1回の送信試行です。重複CronはD1の一意な取得で防ぎ、送信結果不明でも同じ枠では再試行しません。
- 既存の `notification_deliveries.day` に `YYYY-MM-DD:morning` / `YYYY-MM-DD:night` を保存します。過去の日付だけのランダム配信記録とは別扱いで、既存の購読・配信履歴を消しません。履歴は約14日で整理します。
- 対象時刻から10分以内のみ送信します。各Cronは最大50件、同時10件ずつで、最大500登録を処理します。時刻後に登録した端末はその枠の対象外ですが、夜までに登録すれば夜の対象になります。過ぎた枠を昼や翌日にまとめて配信しません。
- 朝と夜の通知を別のタグにし、端末上で同じ通知に置き換わることを防ぎます。通知に写真・利用者名・記録本文は含めません。
- iPhone/iPadはiOS/iPadOS 16.4以降で、Safariからホーム画面に追加してそのアイコンから許可します。Android/PCも通知許可が必要です。
- OSの集中モード、省電力、通信状態、サービスの制限によって遅延・未達があり、定刻の到着や1日2件の到着は保証できません。
- プレビューでは実通知を送信しません。本番AI/通知サーバーへ接続せず、通知の設定は本番サイトにのみ表示します。

## 検証

`node --test tests/*.test.mjs` と `python3 tests/notifications.browser.py` で、時刻境界・同じ日の2枠・重複Cron・期限切れ・登録と停止・許可のタイミングを検証します。実Pushサービスへの配信を証明するテストではありません。
